Usecase:

- This is actually a startup in US healthcare industry.
- It's a desktop application and their primary use case is to automate the diagnosis process by integrating EHR systems with multiple diagnostic lab systems.

Tech stack:

- Medconnect Desktop App: HTML, CSS, JavaScript, Electron.js
- Medconnect API: Node.js, Express.js
- Database: MongoDB, Mongoose
- Storage: Order file upload: SFTP, PDF Upload: AWS S3 - Lab form & Lab Result
- Hosted: Every lab backend on AWS EC2 and has its own db instance.

Workflow:

- Every lab has its own user portal where user configures his role, the EHR and physician details.
- The application has two windows/containers or PODs they are separate instances of chromium browser.
- When user logs into desktop application, the configured EHR opens in left panel and he has to login to the EHR.
- After that he can see list of patients present in that EHR. He can select a patient and click order now button.
- Now that patient's data is collected from EHR. Either we make API call to EHR or if API is not available, that particular page is crawled and data is collected by scraping the UI fields.
- Then we clean it and create an object containing patients data and map it into HL7 Format.
- Right panel: Lab-specific requisition form which is configured on portal opens and populated with patient information and available tests.
- Patient data is mapped and populated on static form sections by parsing HL7 into JavaScript object. Test panel for selected lab is displayed in dynamic section.
- User selects the tests and submits the form. Lab order is placed, the form is processed in backend and data is saved in db.
- The order file is uploaded to SFTP, Order and Result PDF is uploaded to S3 bucket.
- Lab results are available for any given order in a few days.

Terms:

- EHR: Electronic Health Record or Elctronic Medical Record. A digital version of a patient’s medical history, including diagnoses, medications, treatment plans, immunizations, allergies, lab results, and clinical notes. EHRs are designed to be shared across different healthcare settings.
- Labs: Refers to clinical laboratories that perform diagnostic tests (blood, urine, pathology, microbiology, etc.) and the test results they generate for patient care. Labs can use HL7 data format or API.
- LIS: A specialized software system used by laboratories to manage lab workflows, including test ordering, specimen tracking, result entry, quality control, and reporting. LIS typically integrates with EHR/EMR systems to send results to clinicians.
- User Portal: Select EHR + Lab/LIS, add pod configuration
- HL7: Health Level 7 is a set of international standards used to exchange healthcare data between different systems like EHRs, LIS systems, Hospitals, Labs, Billing and insurance systems. The data exchange happens in a predefined format.
- HIPAA: It stands for Health Insurance Portability and Accountability Act is a law in US that deals with security of PHI (Protected Health Information) of people since it is sensitive and easy to misuse or tamper. So as developers we are supposed to follow the process and compliance.

Developed 3 lab requisition forms:

- Different labs have their own kind of requisition form where there are different speciment types and test panels.
- Every form has a static and dynamic part. Static section is the one which is common across all the labs, which is sections like patient demographics, insurance information, physician details etc.
- Dynamic part is something specific to the lab, which has the speciment field and the test panel which is connected to the selected specimen.
- So the labs had different layouts and themes in terms of the colour, logo etc.
- I had used HTML, CSS and JS for the forms due to differences in the layouts. It was a design decision to avoid any UI framework or library.
