# Data Structures & Algorithms, and OOP

## 1. Data Structures & Algorithms

- Data Structures: It is a format of storing and organizing data in order to access or modify it efficiently.
- Data structures are formed and stored in main memory (RAM) at runtime, when program is being executed.
- We structure the data and develop algorithms to access or modify them quickly and efficiently.
- We also structure the data to reduce the memory requirements of the program.
- An algorithm is a sequence of actions which are taken to solve a problem.
- Depending on a particular problem, a particular data structure is chosen and an algorithm is applied on that data structure to solve the problem.
- Data structures vs Database: Data structure reside in primary memory at program runtime. They are temporary.
- Database exists in secondary memory and is permanent.

---

Types of data structures:

1. Linear and non-linear
   - Linear data structures: Arrays, Stack, Queue, Linked list
   - Non linear data structures: Tree, Graph
2. Homogeneous and non homogeneous
   - Homogeneous: all elements have the same type (array). Non-homogeneous: elements can have different types (structure, object).

- Arrays
- Stacks
- Queues
- Linked list, Double linked list, Circular linked list
- Trees, Binary search tree
- Graphs
- Heaps
- 2D Arrays
- Hash table

Quick complexity reference (Big O):

| Structure     | Access              | Search                       | Insert                       | Delete                       |
| ------------- | ------------------- | ---------------------------- | ---------------------------- | ---------------------------- |
| Array         | O(1)                | O(n)                         | O(n)                         | O(n)                         |
| Linked list   | O(n)                | O(n)                         | O(1) at the head             | O(1) at the head             |
| Stack / Queue | O(n)                | O(n)                         | O(1)                         | O(1)                         |
| Hash table    | n/a                 | O(1) average                 | O(1) average                 | O(1) average                 |
| BST           | n/a                 | O(log n) average, O(n) worst | O(log n) average, O(n) worst | O(log n) average, O(n) worst |
| Heap          | O(1) for min or max | O(n)                         | O(log n)                     | O(log n)                     |

STACK EXPRESSIONS: Infix expression, Prefix expression, Postfix expression

- Infix: operator between operands (`A + B`). Prefix: operator before (`+ A B`). Postfix: operator after (`A B +`).
- Computers evaluate postfix easily with a stack. Compilers convert infix to postfix first.

4. Doubly ended queue

- rear, front

- A priority queue is not strictly FIFO. The element with the highest priority leaves first.

1. Single linked list

TREE :

TERMS:

1. Node
2. Root: the top node, with no parent.
3. Parent, Child, Siblings (same parent).
4. Leaf: a node with no children. Internal node: a node with at least one child.
5. Edge: the link between two nodes.
6. Path: the sequence of nodes from one node to another.
7. Level / Depth: distance from the root. The root is at level 0.
8. Height: the number of edges on the longest path from the root to a leaf.
9. Degree: number of children of a node.
10. Subtree: a node with all its descendants.

- Types:
  - Binary tree: each node has at most 2 children. Full (0 or 2 children), complete (all levels filled except maybe the last, filled left to right), perfect (all levels full), skewed (one-sided).
  - Binary search tree (BST).
  - Balanced trees: AVL, Red-Black. They keep the height small.
  - Heap (min and max).
  - B-tree (used in databases), Trie (used for prefix search).
- Formulae: with the root at level 0 and height counted in edges
  - Maximum nodes at level L = 2^L
  - Maximum nodes in a binary tree of height h = 2^(h+1) − 1
  - Minimum height of a binary tree with n nodes = floor(log2 n)
  - Edges in a tree with n nodes = n − 1
  - In a binary tree, leaf nodes = nodes with 2 children + 1

---

Binary Search Tree

- Rule: for every node, left subtree values are smaller and right subtree values are larger.
- Search, insert and delete are O(log n) on average, and O(n) in the worst case (a skewed tree).

BST Traversal methods:

- BFT : Breadth First Traversal
  - Level by level, using a queue.

- DFT : Depth First Traversal:
  1. Inorder Traversal
     - Left, Root, Right. On a BST this gives sorted order.
  2. Preorder Traversal
     - Root, Left, Right. Used to copy a tree.
  3. Postorder Traversal
     - Left, Right, Root. Used to delete a tree.
  - DFT uses recursion or a stack.

---

Spanning Tree :Minimal Spanning tree

- Spanning tree: a subgraph of a connected graph that includes all vertices, has no cycles, and has V − 1 edges.
- Minimal spanning tree (MST): the spanning tree with the smallest total edge weight. Prim's and Kruskal's algorithms find it.

---

GRAPH :

- Terms:
  - Vertex (node) and Edge (connection).
  - Directed (edges have a direction) and Undirected.
  - Weighted (edges have a cost) and Unweighted.
  - Adjacent: two vertices joined by an edge.
  - Degree: number of edges on a vertex (in-degree and out-degree for directed graphs).
  - Path, Cycle (a path that returns to its start), Connected graph (a path exists between every pair).
- Types:
  - Directed, Undirected, Weighted, Unweighted.
  - Cyclic and Acyclic. A directed acyclic graph is a DAG.
  - Connected and Disconnected, Complete graph (every pair is joined).
- Formulae:
  - Maximum edges in an undirected graph with n vertices = n(n − 1) / 2. In a directed graph = n(n − 1).
  - Sum of all degrees = 2 × number of edges (undirected).
  - Adjacency matrix uses O(V²) space. Adjacency list uses O(V + E).
- Graph Traversal algorithms:

1. BFS (Breadth First Search)
   - Uses a queue. Visits neighbours first. Finds the shortest path in an unweighted graph.
2. DFS (Depth First Search)
   - Uses a stack or recursion. Goes as deep as possible first.
   - Both take O(V + E) with an adjacency list.

TEMPLATE, STANDARD TEMPLATE LIBRARY(STL), CONTAINER, ADAPTER, ITERATOR, VECTOR, PAIR : (Data structures using C++)

- Template: generic code that works with any data type (function templates and class templates).
- STL: a library of template-based classes. Its parts are containers, algorithms and iterators.
- Container: holds data. Examples: vector, list, deque, set, map.
- Adapter: wraps another container to give a restricted interface. Examples: stack, queue, priority_queue.
- Iterator: an object that points to an element and moves through a container.
- Vector: a dynamic array that grows automatically.
- Pair: holds two values together, for example `pair<int, string>`.

Array algorithms:

Sorting:

1. Selection sort
2. Insertion sort
3. Bubble sort
4. Merge sort
5. Quick sort
6. Bin or bucket sort
7. Radix sort
8. Multiway merge sort
9. Heap sort

Comparison:

| Sort      | Best                   | Average     | Worst       | Space    | Stable |
| --------- | ---------------------- | ----------- | ----------- | -------- | ------ |
| Selection | O(n²)                  | O(n²)       | O(n²)       | O(1)     | No     |
| Insertion | O(n)                   | O(n²)       | O(n²)       | O(1)     | Yes    |
| Bubble    | O(n) with a swap check | O(n²)       | O(n²)       | O(1)     | Yes    |
| Merge     | O(n log n)             | O(n log n)  | O(n log n)  | O(n)     | Yes    |
| Quick     | O(n log n)             | O(n log n)  | O(n²)       | O(log n) | No     |
| Heap      | O(n log n)             | O(n log n)  | O(n log n)  | O(1)     | No     |
| Bucket    | O(n + k)               | O(n + k)    | O(n²)       | O(n + k) | Yes    |
| Radix     | O(d(n + k))            | O(d(n + k)) | O(d(n + k)) | O(n + k) | Yes    |
| Tim       | O(n)                   | O(n log n)  | O(n log n)  | O(n)     | Yes    |

- Stable: equal elements keep their original order.
- Multiway merge sort is used for external sorting, when the data is too big for memory.
- Tim sort is what JavaScript's `Array.sort` uses in modern engines (V8), and Python's `sort`.

Searching:

1. Linear search (recursive)
2. Linear search (iterative)
3. Binary search (recursive)
4. Binary search (iterative)

- Linear search is O(n) and works on any array. Binary search is O(log n) and needs a sorted array.

Algorithms for minimal spanning tree and shortest path:

1. Prim's Minimal Spanning tree algorithm
2. Kruskal's Minimal Spanning tree algorithm
3. Bellman Ford algorithm
   - Shortest path from one source. Handles negative weights.
4. Floyd and Warshall's algorithm
   - Shortest path between all pairs.
5. A\* algorithm
   - Shortest path using a heuristic to guide the search.
6. Johnson's algorithm for all pairs shortest path
   - Works well on sparse graphs.
7. Dijkstra's Shortest path algorithm
   - Shortest path from one source. Needs non-negative weights.

Concepts:

1. Structures
   - A user-defined type that groups variables of different types under one name.
2. Increment and decrement operators : Pre-increment, Post-increment, Pre-decrement, Post-decrement
   - Pre (`++x`): change first, then use the value. Post (`x++`): use the value first, then change.
3. Asymptotic Notation : Big O
   - Big O is the upper bound (worst-case growth). Omega is the lower bound. Theta is the tight bound.
4. Complexity of algorithm: (Best case, worst case, average case): Time complexity & Space complexity
   - Time: how the running time grows with input size. Space: how the extra memory grows with input size.
5. Hashing
   - A hash function turns a key into an array index, so lookup is O(1) on average.
   - A collision is when two keys get the same index. It is handled with chaining (a list per index) or open addressing (find another slot).
6. Dynamic memory allocation to data structures
   - Memory is requested at runtime from the heap. C uses `malloc` and `free`, C++ uses `new` and `delete`. JavaScript allocates automatically and has garbage collection.

## 2. Object Oriented Programming (OOP)

QUESTIONS:

1. What is Object oriented programming??? What is its significance??
   - A way of writing programs where data and the functions that work on it are bundled together as objects. Its significance is modularity, reuse and easier maintenance, which matters most on large projects.
2. How it is different from procedure oriented programming or structural programming??
   - Procedural code is a set of functions working on shared data, top-down. OOP bundles data and functions into objects and hides the data, bottom-up.
3. Why object oriented programming is popular in software development??
   - It models real-world things, supports reuse through inheritance, hides data for safety, and keeps big codebases organized and easy to change.
4. What difference is between object oriented programming language and object based language??
   - An object-based language supports objects and encapsulation but not full inheritance and polymorphism (for example VB 6). An object oriented language supports all of them (Java, C++, C#). JavaScript is object oriented through prototypes, and the `class` syntax sits on top of that.
5. What are different object oriented programming concepts??
   - Class, Object, Encapsulation, Abstraction, Polymorphism, Inheritance, Dynamic binding, Message passing. Details below.
6. What are the different programming paradigms???
   - Procedural (imperative), Object oriented, Functional, Declarative (SQL, HTML), Logic (Prolog), Event-driven. JavaScript supports several of these.

### 1. CLASS:

- Class is a collection of similar objects.
- It is a blueprint for an object. Like a floor plan is to a building.
- Class is an extension of C structures.
- The main difference between C structures and class is that, structure contains only variables called structure members whereas class contains both variables (data members) and functions (member functions). This is true for C. In C++ a struct can also hold functions. The main difference there is the default access: struct members are public by default, class members are private.
- The data members and member functions can be private or public or protected.
- Memory allocation does not happen on creation of class.

### 2. OBJECT:

- An object is anything which has some attributes, certain behavior or properties is an object.
- An object is the instance of class.
- An object is a variable of type class.
- Memory is allocated or reserved on creation of objects.

### 3. ENCAPSULATION:

- Binding the data members of the object with its member functions.
- Data hiding: keep data members private and give access through public methods (getters and setters). This protects the data from wrong changes.

### 4. ABSTRACTION:

- Knowing only necessary data. Not knowing how the object does its work. You do know the behavior (what it does). What you don't see is the implementation (how it does it).
- Abstraction hides complexity (what to expose). Encapsulation hides data (how to protect it).

### 5. POLYMORPHISM:

- The term ‘polymorphism’ comes from a combination of Greek words, ‘Poly’ meaning many and ‘Morph’ meaning form. Hence polymorphism means the ability to gain many forms.
- Many forms for same thing. Different behavior for different caller.
- Compile-time polymorphism: overloading. Runtime polymorphism: overriding.

### 6. OVERLOADING:

- Assigning more than one meaning to a function or a symbol is called overloading.
- There are two types of overloading: Operator overloading and function overloading.
- Java and C++ support function overloading. C++ also supports operator overloading. Java does not. JavaScript supports neither.

### 7. FUNCTION OR METHOD OVERLOADING:

- Same method name, different parameters (number or types), in the same class. The compiler picks the right one at compile time.

```java
int add(int a, int b) { return a + b; }
double add(double a, double b) { return a + b; }
int add(int a, int b, int c) { return a + b + c; }
```

### 8. METHOD OVERRIDING:

- A child class gives its own implementation of a method that the parent class already has. Same name and same parameters. The method that runs is chosen at runtime (dynamic binding).

```java
class Animal { void sound() { System.out.println("..."); } }
class Dog extends Animal { void sound() { System.out.println("Bark"); } }
```

### 9. OPERATOR OVERLOADING:

- Giving an operator (`+`, `==`, `<<`) a new meaning for your own class, so `a + b` works on objects. Supported in C++, not in Java or JavaScript.

### 10. INHERITANCE:

- A child class takes the properties and methods of a parent class. It supports reuse and the “is-a” relationship (a Dog is an Animal).
- Types: single, multilevel, hierarchical, multiple, hybrid. Java and JavaScript do not allow multiple inheritance of classes.
- 10.1 : ASSOCIATION: A general “uses” relationship between two classes. Both objects live independently (a Teacher and a Student).
- 10.2 : COMPOSITION: A strong “has-a” relationship. The part cannot exist without the whole. If the whole is destroyed, the parts go too (a House and its Rooms).
- 10.3 : AGGREGATION: A weak “has-a” relationship. The part can exist without the whole (a Team and its Players).

### 11. COUPLING:

- It is the measure of dependency between two functions.
- The same idea applies between modules and classes.
- It must be low.

### 12. COHESION:

- It is the measure of dependency between two statements within a module or a function.
- In simple words, how closely the things inside a module belong together.
- It must be high.
- A good code has low coupling and high cohesion.
- It promotes code reusability.

### 13. CONSTRUCTOR:

- A special method that runs automatically when an object is created, to initialize it. In C++ and Java it has the same name as the class. In JavaScript it is `constructor()`.
- Types: default (no parameters), parameterized, copy (C++).

### 14. DESTRUCTOR:

- A special method that runs when an object is destroyed, to release resources. In C++ it is `~ClassName()`.
- Java and JavaScript have no destructors. The garbage collector frees memory automatically.

### 15. DYNAMIC BINDING and MESSAGE PASSING

- Dynamic binding: the method that runs is decided at runtime, from the actual object type (this is how overriding works).
- Message passing: objects communicate by calling each other's methods.
