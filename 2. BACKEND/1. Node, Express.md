**NODE JS:**

- Javascript **runtime environment** which runs on **Google** **chrome's V8 javascript engine**.
- Executes **outside** the browser.
- **Single threaded**: It executes one main thread sequentially so the code runs line by line. Your JavaScript runs on one thread, but Node itself uses extra threads internally (the libuv thread pool and worker threads).
- **Event loop:** Async tasks are handled by the **event loop** , so the main thread never blocks. Only as long as you don't run heavy synchronous code. A long loop on the main thread blocks every request.
- Has **Non blocking I/O**: Uses **libuv** library to perform I/O operations. libuv is a C library. It provides the event loop and a thread pool (4 threads by default) used for fs, dns, crypto and zlib. Network I/O uses OS-level async mechanisms, not the thread pool.
- **Worker threads:** For CPU-heavy tasks, Node.js supports **worker threads** to run JavaScript in **parallel** in separate threads. Each worker is its own thread with its own V8 instance and event loop. The libuv thread pool is a different thing. For CPU-heavy work you can also use `child_process` or `cluster`.
- **Event driven**: Supports **asynchronous code** execution.
- Uses promises, callbacks and async/await.
- Has **built in modules** for various functionalities - like file handling, encryption, data fetching etc. Examples: `fs`, `path`, `http`, `crypto`, `events`, `stream`, `os`.
- Modules are written in JavaScript & C++ language
- Cross platform, Rich ecosystem, Scalable, real time applications
- Free, open-source, MIT license.
- Current version: LTS v24.x (Dec 2025). Only even-numbered releases become LTS.

**Event loop:**

- Phases in order: **timers**, pending callbacks, idle/prepare, **poll**, **check**, close callbacks.
- timers runs `setTimeout` and `setInterval` callbacks. poll picks up new I/O events. check runs `setImmediate` callbacks.
- Between every phase (and after each callback), Node drains `process.nextTick` first, then promise microtasks.
- `setTimeout(fn, 0)` vs `setImmediate(fn)`: from the main module the order is not guaranteed. Inside an I/O callback, `setImmediate` always runs first.

**Blocking vs non-blocking code:**

- **Blocking**: the main thread waits until the operation finishes and nothing else runs. Example: `fs.readFileSync`.
- **Non-blocking**: the operation is handed off, the main thread moves on, and a callback or promise handles the result later. Example: `fs.readFile` or `fs.promises.readFile`.
- In a server, one blocking call stalls every request.

**Other core concepts:**

- **Modules**: CommonJS (`require`, `module.exports`) vs ES modules (`import` and `export`, needs `"type": "module"` or the `.mjs` extension).
- **Streams**: process data in chunks instead of loading it all in memory. Four types: readable, writable, duplex, transform.
- **Buffer**: fixed-size raw binary data.
- **EventEmitter**: the base of most Node APIs (`on`, `emit`).
- **cluster**: one process per CPU core to use all cores. Different from worker threads, which live inside one process.

**EXPRESS JS:**

- Fast, lightweight, minimalist framework
- Building **web applications** and **APIs** with Node js
- Supports **middlewares** to intercept and process requests and responses
- express.json() for JSON, express.static() for serving static files and express.urlencoded() for form data.
- Supports **routing**
- Supports templating engines
- RESTful API Development
- Static file serving
- Unopinionated - so we don't have to follow a fixed project structure
- Current version: v5.x (Dec 2025)
- v5 is the default on npm now. A key change: errors thrown in async handlers, and rejected promises, go to the error handler automatically.

**Concepts:**

- **Middleware**: a function with `(req, res, next)` that runs between the request and the response. It can change `req` and `res`, end the response, or call `next()`.
- **next()**: passes control to the next middleware. `next(err)` skips to the error-handling middleware.
- **app.use()**: registers middleware for all methods, optionally under a path. It runs in the order you register it, so order matters.
- **Error-handling middleware** has four arguments: `(err, req, res, next)`, and is registered last.
- **Templating engine**: renders HTML on the server by merging a template with data, using `res.render()`. Examples: ejs, pug, handlebars. Set with `app.set('view engine', 'ejs')`.
- **Static rendering**: `express.static('public')` serves files (css, js, images) as they are from a folder, with no processing.

**Request properties:**

- req.body: It is undefined unless a body parser such as `express.json()` is used.
- req.params: Route parameters, for `/users/:id`.
- req.query: The query string, for `?page=2`.
- req.method
- req.url
- req.originalUrl - keeps the full original URL.
- req.session - used to manage session. It is not core Express. It comes from the express-session middleware.
- req.headers, req.cookies (needs cookie-parser), req.ip

**Response methods:**

- res.send() - send string in response. It also sends buffers, objects and arrays.
- res.json() - send json in response
- res.status()
- res.redirect()
- res.render()
- res.set()
- res.cookie()
- res.sendFile(), res.download(), res.sendStatus(), res.end(), res.clearCookie(), res.type()

**WEB SERVER:**

- Web server: A software installed on server that handles http requests and sends response. Eg: Apache HTTP Server, Nginx, Microsoft IIS, Node.js `http` module.
- Apache HTTP server: general-purpose web server, written in C.
- Apache Tomcat: Java. A servlet container / application server for Java.
- IIS (Internet Information Services): Microsoft .NET. Microsoft's web server for Windows. It hosts ASP.NET apps.
- nginx: Web server, reverse proxy and load balancer. Commonly placed in front of Node apps.
- WAMP server: PHP. WAMP is a bundle: Windows + Apache + MySQL + PHP. Similar bundles: LAMP (Linux), XAMPP.

**NODEMON:**

- A dev tool that watches files and restarts the app automatically on changes.
- Install: `npm install --save-dev nodemon`. Run: `nodemon app.js`, or add a `dev` script in package.json.
- For development only, not production. Node also has a built-in alternative: `node --watch app.js`.

**NVM – Node version manager:**

- Used to work with multiple node js versions in the system. Useful for testing, debugging, checking new features.
- Download and install exe. This is nvm-windows. On Mac and Linux the tool is nvm-sh, installed with a script.
- nvm --version: Check nvm version
- nvm list: List all node js versions
- nvm install 18.20.2 OR nvm install 22.23.1 OR nvm install 24.18.0 : Install specific versions
- nvm list available: shows the real ones.
- nvm use 18.20.2 OR nvm use 22.23.1 OR nvm use 24.18.0 : Use specific version among installed
- nvm install lts: Install latest LTS node. On nvm-sh the command is nvm install --lts.
- nvm install latest: Install latest node

Switch versions for projects:

```
cd my-old-project
nvm use 18.20.2

cd ../my-new-project
nvm use 24.18.0
```

Tip: a `.nvmrc` file in the project (nvm-sh) pins the version for that project.

**PM2 in node js - Process manager for node applications:**

- Keeps the app running: restarts it on a crash, and can start it on server reboot.
- Cluster mode: `pm2 start app.js -i max` runs one instance per CPU core.
- Built-in logs and monitoring.
- Commands: `pm2 start app.js`, `pm2 list`, `pm2 logs`, `pm2 restart <name>`, `pm2 stop <name>`, `pm2 save`, `pm2 startup`.

**Package manager: NPM & YARN**

1. Install: npm install `<package-name>`@`<version>`, yarn add `<package-name>`@`<version>`. npm install lodash@^4.0.0, yarn add lodash@^4.0.0 => ^ allows minor and patch (4.x.x, but not 5.0.0) and \~ for patch updates only (4.0.x).
2. Uninstall: npm uninstall foo, yarn remove foo
3. dev dependencies: --save-dev. The short form is `-D`. In Yarn: `yarn add --dev foo`.

Also know:

- `package.json` lists dependencies and scripts. `package-lock.json` locks exact versions.
- `dependencies` vs `devDependencies`: dev ones are only for development (nodemon, test tools).
- `npm ci`: clean install strictly from the lock file (used in CI).
- `npx`: runs a package without installing it globally.
- `npm install -g`: global install.

**FRAMEWORK:**

- A framework is a set of pre-written code that provides a structure for developing software applications.
- It is a layer between application and OS. More precisely, a framework sits between your application code and the language runtime or platform (Express on Node.js, Spring Boot on the JVM), not directly on the OS.
- A framework is usually built for one language. Express is for JavaScript, Django for Python, Spring Boot for Java. A platform like .NET supports several languages (C#, F#, VB).
- A framework does not convert code into OS or system understandable instructions. That job belongs to the compiler, interpreter or runtime (V8 for Node.js, the JVM for Java). The framework is pre-written code that runs on top of it.
- It speeds up the development process because programmers don't have to write code from scratch.
- It makes applications compatible due to standardisation.
- It's like a frame or a template for application development.
- Popular frameworks for different technologies:
  1. Java: Spring Boot
  2. C#: Microsoft .NET
  3. Node JS: Express, NestJS, Fastify, Koa
  4. Python: Django, Flask
  5. PHP: Laravel, Yii
  6. Ruby: Ruby on Rails
  7. Angular framework
  8. React: Javascript library, Next JS: Framework for React

**LIBRARY:** Collection of pre-written code that can be used to perform specific tasks. Framework vs library: you call a library, but a framework calls your code (inversion of control).

Package/Dependencies managers for libraries in different technologies:

1. Java: Maven, Gradle
2. MS .NET: NuGet
3. Node JS: NPM, Yarn, pnpm
4. Python: PIP
5. Dart, Flutter: Pub
