# 2. Concepts Involved and Explanation

## Node.js Application

Created a simple Express server exposing one endpoint (`/`) that returns:

- Welcome message
- Hostname of the pod

### Why return hostname?

- Every Kubernetes Pod has its own hostname.
- Returning the hostname helps identify which pod handled the request.
- Useful for verifying load balancing.

---

## Docker

Docker packages:

- Application code
- Runtime
- Dependencies
- Configuration

into a single unit called an **Image**, which runs as a **Container**.

---

## Dockerfile

Blueprint used to build a Docker Image.

Contains instructions such as:

- Base image
- Working directory
- Copy source files
- Install dependencies
- Expose application port
- Start the application

---

## Docker Image

A read-only packaged version of the application containing:

- Source code
- Node runtime
- Installed packages

One image can create multiple containers.

---

## Docker Container

A running instance of a Docker image.

---

## Minikube

Minikube creates a **single-node Kubernetes cluster locally** for learning and development.

Started using:

```bash
minikube start --driver=docker
```

---

## kubectl

CLI tool used to communicate with Kubernetes.

Common commands:

```bash
kubectl get pods
kubectl get svc
kubectl apply -f deployment.yaml
kubectl delete -f deployment.yaml
```

---

## Pod

- Smallest deployable unit in Kubernetes.
- Contains one or more containers.
- Our Node application runs inside Pods.

---

## Deployment

Deployment manages Pods automatically.

Responsibilities:

- Creates Pods
- Maintains desired number of replicas
- Restarts failed Pods
- Self-healing
- Rolling updates

---

## Replica

Defines how many identical Pods Kubernetes should maintain.

Example:

```yaml
replicas: 2
```

Kubernetes always tries to keep 2 Pods running.

---

## Labels

Used to identify Kubernetes resources.

Example:

```yaml
labels:
  app: node-app
```

---

## Selectors

Used by Services to identify target Pods.

Example:

```yaml
selector:
  app: node-app
```

---

## Service

Provides:

- Stable network endpoint
- Load balancing
- Communication with Pods

Pods can be replaced, but the Service IP remains stable.

---

## NodePort Service

Exposes the application outside the cluster.

Flow:

```
Browser
      ↓
NodePort
      ↓
Service
      ↓
Pod
```

---

## Container Port vs Service Port

Container Port

```
3000
```

Application listens here.

Service Port

```
80
```

Incoming traffic arrives here.

Traffic forwarding:

```
80 → 3000
```

---

## Image Pull Policy

Used in Deployment:

```yaml
imagePullPolicy: IfNotPresent
```

Meaning:

- Use local image if available.
- Pull image only if it doesn't exist.

Useful for Minikube local development.

---

## Minikube Docker Daemon

One of the most important concepts.

Minikube has its **own Docker daemon**.

Docker Desktop Docker and Minikube Docker are different.

If image is built in Docker Desktop,
Minikube cannot access it.

Switch Docker to Minikube using:

```powershell
minikube docker-env | Invoke-Expression
```

Then rebuild the image.

---

## Desired State

Kubernetes is declarative.

Instead of saying:

> Create two Pods.

We say:

> I want two Pods.

Kubernetes continuously ensures that desired state exists.

---

## Service Endpoints

Command:

```bash
kubectl get endpoints node-service
```

Displays Pod IPs attached to the Service.

Example:

```
10.244.x.x
10.244.x.x
10.244.x.x
```

This confirms that the Service is connected to multiple Pods.

---

## Load Balancing

Service distributes traffic among Pods.

Browser refresh does **not** always show different Pods because:

- Browser reuses TCP connections (HTTP Keep-Alive)
- Kubernetes load balances per connection

Better verification methods:

- kubectl get endpoints
- curl
- Pod logs

---

## Windows + Minikube Networking

Direct access:

```
http://<minikube-ip>:30007
```

did not work because of Windows + Docker networking limitations.

Correct approach:

```bash
minikube service node-service
```

or

```bash
minikube service node-service --url
```

# 5. Challenges Faced, Root Cause and Solutions

| Challenge                                                     | Root Cause                                                      | Solution                                                                              |
| ------------------------------------------------------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------------------- |
| `kubectl apply -f .` tried reading `package.json`             | Application files and Kubernetes manifests were in same folder  | Created a separate`kubernetes/` folder and applied only that directory                |
| `ImagePullBackOff` / `ErrImagePull`                           | Docker image built in Docker Desktop instead of Minikube Docker | Ran`minikube docker-env \| Invoke-Expression`, rebuilt image and restarted deployment |
| kubectl version warning                                       | kubectl client version newer than cluster version               | Continued since it was only a compatibility warning                                   |
| Browser always showed same hostname                           | Browser reused TCP connection                                   | Verified load balancing using endpoints, curl and pod logs                            |
| `curl` failed in PowerShell                                   | `curl` is an alias for `Invoke-WebRequest`                      | Used`curl.exe` instead                                                                |
| Could not access`http://<minikube-ip>:30007`                  | Windows + Docker driver networking limitation                   | Used`minikube service node-service`                                                   |
| PowerShell`cd` failed                                         | Folder path contained spaces                                    | Wrapped path in double quotes                                                         |
| `minikube docker-env \| Invoke-Expression` produced no output | Command silently sets environment variables                     | Verified using`docker info` and continued                                             |

# Key Takeaways

- Build Docker images inside Minikube Docker.
- Keep Kubernetes manifests inside a dedicated `kubernetes/` folder.
- Deployment manages Pods.
- Service exposes Pods and provides load balancing.
- Verify Kubernetes using:
  - `kubectl get`
  - `kubectl describe`
  - `kubectl logs`
  - `kubectl get endpoints`
- Browser refresh is not a reliable way to verify load balancing.
- On Windows + Minikube, use `minikube service` to access applications.
