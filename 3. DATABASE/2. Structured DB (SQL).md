## 1. SQL and relational databases

**SQL: Structured Query Language**

- **Relational Database:** A database that stores data in structured tables with predefined relationships.
  - *Correction:* the word 'relational' comes from **relation**, the mathematical term for a table (a set of rows). It does not mean 'tables are related to each other'. Foreign keys do link tables, but that is not where the name comes from.
- Relational databases store data in tables with **fixed schemas**.
- *Correction:* SQL is the **language**. The systems that implement it are **RDBMS** (Relational Database Management Systems), e.g. MySQL, PostgreSQL. Structured data is stored and handled in an RDBMS.
- Queries are 'fired' in any RDBMS to retrieve the data, and the fired query 'hits' a particular table in the database.
- SQL can execute queries against a database. It can retrieve data from a database, insert, update, delete records in a database.
- It can create new databases, create new tables in databases, create stored procedures in database, create views in database, and can set permissions on tables, procedures, and views.

## 2. Concepts

- **Table:** A structured collection of rows and columns used in relational databases. In an RDBMS like MySQL data is stored in the form of database objects called tables. A database can contain multiple tables, and tables can be linked to each other through keys.
- **Row / Record:** Horizontal entry, an individual entry in a table representing one entity instance.
- **Column / Field:** Vertical entity, an attribute for all the records that holds the same type of data for all records.
- **Views:** Virtual tables created from SQL queries.
- **Stored Procedures:** SQL code stored in the database and run on the server. *Correction:* the notes said 'precompiled'. Whether it is precompiled or just has its plan cached depends on the engine.
- **Triggers:** Automatically executed code on insert / update / delete events.

For schema, entity relationships, ER diagrams, design flow and seeding, see document 1 (DBMS First Principles), section 7.

## 3. Keys

A key is an attribute/column or set of attributes/columns used to **uniquely identify records** in a table and to **establish relationships** between tables.

1. **Primary key:** A column (or combination of columns) that uniquely identifies each row in a table. It **cannot contain NULL values** and must be unique.
2. **Foreign key:** A column in one table that refers to the **primary key of another table**. It is used to **maintain relationships and referential integrity**.
3. **Composite key:** A primary key formed using **multiple columns** when a single column is not sufficient for uniqueness.
4. **Candidate key:** Columns that can uniquely identify a row. One of them is chosen as the primary key.
5. **Unique key:** *(added)* Enforces that all values in a column are unique. Unlike a primary key it can allow NULL, and a table can have many unique keys.
6. **Alternate key:** *(added)* A candidate key that was not chosen as the primary key.

## 4. Joins

A SQL operation used to **combine rows from two or more tables** based on a related column.

1. **Inner join:** Returns only the records that have **matching values** in both tables.
2. **Left join / Left outer join:** Returns all records from the **left table** and matching records from the right table. Non-matching rows from the right table return NULL.
3. **Right join / Right outer join:** Returns all records from the **right table** and matching records from the left table. Non-matching rows from the left table return NULL.
4. **Full join / Full outer join:** Returns all records when there is a match in **either** table. Non-matching rows return NULL on the missing side. Full join is not supported in MySQL. *Correction:* emulate it with `LEFT JOIN ... UNION ... RIGHT JOIN`. PostgreSQL supports `FULL JOIN` natively.
5. **Self join:** *(added)* A table joined with itself, e.g. an employee table joined to itself to find each employee's manager.
6. **Cross join:** *(added)* Every row of one table paired with every row of the other (Cartesian product).
7. **Natural join:** *(added)* Joins automatically on all columns with the same name in both tables. Risky in practice, prefer explicit `ON`.
8. **Hash join:** *(correction)* not a join type like the ones above. It is an **algorithm** the database may choose to execute a join (build a hash table on the smaller table, probe it with the other). Others are nested loop and merge join.

## 5. Normalization

Process of **organizing data** in a database to **reduce redundancy**, **eliminate duplicate data** and **improve data integrity**.

**Normal Forms**

1. **1NF (First Normal Form):** Atomic values (no repeating groups or multi-valued attributes). Each column contains single values only.
2. **2NF (Second Normal Form):** Must be in 1NF. No partial dependency (a non-key attribute should depend on the entire primary key).
3. **3NF (Third Normal Form):** Must be in 2NF. No transitive dependency (non-key attributes should not depend on other non-key attributes).

*(added)* Why normalize: duplicated data causes **update, insert and delete anomalies**. If a customer's address is stored on every order row, changing it means updating many rows, and missing one leaves the data contradicting itself.

**DENORMALIZATION:** Process of **intentionally introducing redundancy** into a database to **improve read performance**. *(added)* Cost: writes get slower and duplicated copies can drift apart, so do it only for a measured read problem.

## 6. Commands

**SQL data types:** INT, VARCHAR, CHAR, DATE, TIMESTAMP, DECIMAL, BOOLEAN.

**Command categories**

1. **DML** (Data Manipulation Language): Select, Update, Insert, Delete (**SUID**)
2. **DDL** (Data Definition Language): Drop, Alter, Create, Truncate (**DACT**)
3. **DCL** (Data Control Language): Grant, Revoke (**GR**)
4. **TCL** (Transaction Control Language): Savepoint, Rollback, Commit (**SCR**)

**Basic commands (MySQL shell)**

```sql
show databases;              -- display existing databases
create database test;        -- create a new database named 'test'
use test;                    -- switch to the database 'test'
show tables;                 -- display all tables of the current database
source C:\Users\admin\Desktop\Db\demobld.sql   -- load a readymade database (here 'demobld')
select * from emp;           -- display the whole 'emp' table
desc emp;                    -- describe 'emp': columns and their constraints
```

- Do not give a semicolon at the end of the `source` command.
- Creating a new table column: ColumnName - DataType - Constraints. Eg: `DeptId int NOT NULL UNIQUE`

**CREATE**

```sql
CREATE DATABASE db_name;
CREATE TABLE table_name (col_1 datatype, col_2 datatype, ...);
INSERT INTO table_name VALUES (value1, value2, value3, ...);
INSERT INTO table_name (column1, column2, column3, ...) VALUES (value1, value2, value3, ...);
```

**READ**

```sql
SELECT * FROM table_name;    -- * is the wildcard, returns all columns
SELECT col_1, col_2, col_3 FROM table_name WHERE condition;
```

**UPDATE**

```sql
UPDATE table_name SET column1 = value1, column2 = value2, ... WHERE condition;
```

**DELETE**

```sql
DELETE FROM table_name WHERE condition;
DELETE FROM table_name;      -- deletes ALL rows, the table itself stays
DROP TABLE table_name;       -- deletes the table itself
```

*Correction:* the notes said `DELETE FROM table_name;` 'deletes entire table'. It removes all rows, not the table.

**Operators**

1. `AND`: Logical AND
2. `OR`: Logical OR

**Aggregate functions**

1. `sum(...)`: returns the sum of elements of the argument column.
2. `avg(...)`: returns the average of elements of the argument column.
3. `max(...)`: returns the maximum value of the elements of the argument column.
4. `min(...)`: returns the minimum value of the elements of the argument column.
5. `count(...)`: returns the count (number of elements) of the argument column.

**Keywords to be used**

```sql
where ... in (..., ..., ...);
where ... not in (..., ..., ...);
where ... or ...;
where ... and ...;
where ... between ... and ...;
where ... like ...;              -- % = any characters, _ = one character
group by ... having ...;         -- having filters groups, after group by
order by ... [asc | desc];
concat(left(..., n), '...', right(..., n), '...');
```

*Corrections:* `BETWEEN` always takes `AND` (the notes also listed `between ... or ...`, which is invalid, use two conditions joined by OR). `HAVING` belongs with `GROUP BY`, not `ORDER BY`.

**Set operations in SQL**

1. `UNION`: combines results, removes duplicates
2. `UNION ALL`: combines results, keeps duplicates
3. `INTERSECT`: rows present in both results
4. `MINUS`: rows in the first result not in the second

*Correction:* `MINUS` is Oracle. MySQL and PostgreSQL use `EXCEPT`. MySQL supports `INTERSECT` and `EXCEPT` only from version 8.0.31.

**SQL constraints**

1. `UNIQUE`
2. `NOT NULL`
3. `CHECK`
4. `DEFAULT`
5. `INDEX` (as in clustering index and non clustering index, see document 1, section 4)

**Other**

1. Use `--` for a single line comment (MySQL needs a space after the dashes).
2. Use `/* ........ */` for a multiline comment.
3. `floor()`: round figure to the lower side
4. `ceil()`: round figure to the higher side
5. `curdate()`: returns the current date (MySQL)
6. `now()`: returns the current date and time (MySQL). *Correction:* the notes listed `getdate()`, which is SQL Server, not MySQL.
