# Non-Structured DB (MongoDB)

*Reorganized from my notes. Wrong lines are corrected, nothing is removed. Lines marked (added) are new.*

MongoDB is a **document (NoSQL, semi-structured)** database, not truly 'unstructured'. For general database ideas (indexing, transactions, replication, sharding, design) see document 1 (DBMS First Principles).

## 1. Overview

- MongoDB is a **distributed, document-oriented NoSQL** database storing data in **JSON-like documents**.
- It internally stores data in **Binary JSON (BSON)**, a binary-encoded format that is faster to parse and supports more data types than JSON.
- It uses a **flexible, schema-less design** so that we can use dynamic data structures. Although we can put **schema validation** using **Mongoose** (application level). *Correction:* MongoDB itself also has **native validation** with `$jsonSchema` (see the Commands section).
- **High availability:** achieved through replica sets that provide automatic failover and redundancy.
- **Horizontal scaling:** done using sharding to distribute data across multiple servers for large workloads.
- **Aggregation pipeline:** a powerful framework to transform, filter, and analyze data in stages.
- **ACID transactions:** supported since MongoDB 4.0 for multi-document operations (on replica sets, and on sharded clusters from 4.2), ensuring atomicity, consistency, isolation, and durability. *(added)* They cost performance, so the usual design is to avoid needing them.
- **Rich indexing:** supports text, geospatial, compound, and other indexes for faster query performance.
- **Current version:** *Correction:* the notes said v7.x (Dec 2025). The 8.x series is current, so check the MongoDB site for the exact latest release.
- Hierarchy: Database => Collections => Documents

**Terms mapped to SQL** *(added)*

| SQL | MongoDB |
| --- | --- |
| Database | Database |
| Table | Collection |
| Row / Record | Document |
| Column | Field |
| Join | `$lookup` (or embedding) |
| Primary key | `_id` |

## 2. Concepts

- **Collections:** A group of documents stored together without a fixed schema. It is equivalent to a table in relational databases.
- **Documents:** A JSON-like structure containing key-value pairs with flexible fields. It is the basic unit of data in MongoDB. A collection is made up of a lot of documents. A document is similar to a record in a structured db.
- **BSON:** Binary JSON used internally by MongoDB for storage and queries. It supports additional data types and improves performance.
- **BSON data types:** Includes ObjectId, Date, Decimal128, Binary. These types allow accurate representation of real-world data.
- **Schema-less design:** *Correction:* by default MongoDB does not enforce a schema at the database level, but you can add **optional validation** rules with `$jsonSchema`. Schema design is mostly handled at the application level.
- **Embedding:** Related data is stored in the same document. This improves read performance and reduces joins.
- **Referencing:** Related data is stored in separate documents using references. This avoids data duplication and is useful for large datasets.
- **ObjectId:** Default value for the `_id` field that uniquely identifies a document. *Correction:* it is 12 bytes: a 4-byte **timestamp**, a 5-byte **random value** and a 3-byte **counter**. The notes said 'machine information', which is how older versions worked.
- **ObjectId ordering:** ObjectIds are roughly time-ordered. This helps in sorting and pagination.
- **Index:** A data structure that speeds up read queries. Indexes increase storage usage and write cost.
- **Aggregation:** *Correction:* the notes described it as 'query a collection and get an id, then search another collection using the same id, like a join'. That describes **`$lookup`**, one stage inside aggregation. Aggregation as a whole is processing documents through a pipeline.
- **Aggregation framework:** Used for data processing and analytics. It works using a pipeline of stages.
- **Aggregation pipeline:** Each stage processes documents and passes results forward. Common stages include `$match`, `$group`, `$sort`, `$project`.
- **Replica set:** A group of MongoDB instances with one primary (the others are secondaries). Automatic failover occurs if the primary fails.
- **TTL index:** Automatically deletes documents after a specified time. Commonly used for logs and session data.
- **Capped collection:** Fixed-size collection that maintains insertion order. Old documents are removed when the size limit is reached.
- **GridFS:** Used to store large files like videos or images. Files are split into chunks and stored across collections. *(added)* It exists because a single document is limited to 16 MB.

## 3. Commands

### Basic commands

- Create / switch to a database: `use <database_name>` *(added: the database is actually created when you first insert data)*
- Show all databases: `show dbs`
- Show current database: `db`
- Drop a database: `db.dropDatabase()`
- Create a collection: `db.createCollection("collection_name")`
- Show all collections: `show collections`
- Drop a collection: `db.collection_name.drop()`
- List collection stats: `db.collection_name.stats()`

### Create (insert operations)

```js
db.collection_name.insertOne({ key: value });
db.collection_name.insertMany([{ key1: value1 }, { key2: value2 }]);
```

### Read (query operations)

```js
db.collection_name.find();                                   // all documents
db.collection_name.find({ key: value });                     // with a condition
db.collection_name.findOne({ key: value });                  // one document
db.collection_name.find({ key: value }, { field1: 1, field2: 1 });   // projection
db.collection_name.find().sort({ field: 1 });                // sorting (1 asc, -1 desc)
db.collection_name.find().limit(5);                          // limit
db.collection_name.find().skip(5).limit(5);                  // pagination
db.collection_name.countDocuments({ key: value });           // count
db.collection_name.distinct("field_name");                   // distinct values
```

### Update (update operations)

```js
db.collection_name.updateOne({ filter }, { $set: { field: value } });
db.collection_name.updateMany({ filter }, { $set: { field: value } });
db.collection_name.replaceOne({ filter }, { newDocument });
// upsert (update or insert if not found)
db.collection_name.updateOne({ filter }, { $set: { field: value } }, { upsert: true });
```

### Delete (remove operations)

```js
db.collection_name.deleteOne({ filter });
db.collection_name.deleteMany({ filter });
```

### Index operations

```js
db.collection_name.createIndex({ field: 1 });
db.collection_name.getIndexes();
db.collection_name.dropIndex("index_name");
db.collection_name.dropIndexes();
```

### Aggregation operations

```js
// basic aggregation
db.collection_name.aggregate([
  { $match: { key: value } },
  { $group: { _id: "$field", total: { $sum: 1 } } }
]);
```

Stages:

- Match documents: `{ $match: { key: value } }`
- Group documents: `{ $group: { _id: "$field", total: { $sum: 1 } } }`
- Project fields: `{ $project: { field1: 1, field2: 1 } }`
- Sort documents: `{ $sort: { field: 1 } }`
- Limit number of documents: `{ $limit: 5 }`
- Skip documents (pagination): `{ $skip: 5 }`
- Add a new field: `{ $addFields: { newField: { $sum: ["$field1", "$field2"] } } }`
- Lookup (join collections): `{ $lookup: { from: "otherCollection", localField: "field", foreignField: "field", as: "joinedData" } }`
- Unwind an array: `{ $unwind: "$arrayField" }`

### Operators

- `$lt`: less than
- `$gt`: greater than
- `$gte`: greater than or equal to
- `$eq`: equal
- `$ne`: not equal
- `$in`: in
- `$nin`: not in
- `$and`: logical AND, syntax `{ $and: [ {condition 1}, {condition 2}, {condition 3} ] }`
- `$or`: logical OR, syntax `{ $or: [ {condition 1}, {condition 2}, {condition 3} ] }`
- Comparison syntax: `{ field: { $gt: value } }` (same pattern for `$lt`, `$gte` etc.)

### Data validation and schema operations

Enable validation for a collection:

```js
db.createCollection("collection_name", {
  validator: {
    $jsonSchema: {
      bsonType: "object",
      required: ["field1", "field2"],
      properties: {
        field1: { bsonType: "string" },
        field2: { bsonType: "int" }
      }
    }
  }
});
```

- Get collection validation settings: `db.getCollectionInfos({ name: "collection_name" })` and read `options.validationLevel`. *Correction:* the notes used `db.collection_name.getValidationLevel()`, which I could not confirm as a valid method, so I replaced it with the documented way.

### Backup and restore operations (bash)

```bash
mongodump --db <database_name> --out <backup_directory>
mongorestore --db <database_name> <backup_directory>
```

### Miscellaneous

- Get current server status: `db.serverStatus()`
- Get server build information: `db.buildInfo()`
- List all active operations: `db.currentOp()`
- Enable or disable profiling: `db.setProfilingLevel(2)` // 0 off, 1 slow queries, 2 all queries
- To start mongodb: in cmd `mongod`
- To use shell: in cmd `mongosh`
- To clear screen: `cls`
- `pretty()`: to show data properly (*added:* mongosh already prints pretty by default)

## 4. Installation and setup

1. **MongoDB:** Download and install / extract the mongodb server setup. Set the path up to the bin folder in environment variables.
2. **MongoDB Shell**
3. **MongoDB CLI Tools:** mongoimport, mongoexport, mongodump, mongorestore etc. Allow us to perform operations on the DB using CLI. The same operations can be performed using Compass as well.

**Steps**

1. Download mongodb shell and mongodb command line database tools from the downloads section of the mongodb website.
2. Extract the zip file of both in the same location where the mongodb server folder is present in program files.
3. Run the exe of the shell file.
4. Set the environment variable for both mongodb cli and mongodb shell. Path must be up to inside of the bin folder (where the exe file is located).

- To start mongodb: in cmd `mongod`
- To use shell: in cmd `mongosh`
- **Taking a local backup of a mongodb cluster:** install the CLI tools (it should have mongodump). Command:

```bash
mongodump --uri="connection_string" --out "path_of_folder_where_db_stored_locally"
```

The folder path can be copied from the Windows Explorer address bar. *(Correction: the notes were missing a space after `--out`.)*

- **Restoring the databases from a folder:**

```bash
mongorestore --uri "mongodb://localhost:27017" --dir "folder_where_local_backup_is_stored"
```

## 5. Atlas and Compass

**Atlas:** Fully managed, cloud based, multi-platform (AWS, Azure, GCP), database as a service.

**Compass:** GUI tool for MongoDB.

1. Create an organization under an Atlas account
2. Create projects under the organization
3. Create clusters under a project
4. Create a database in clusters

A cluster can have multiple databases and each database can have multiple collections.

Atlas => Organizations => Projects => Clusters (DB server instance) => Database => Collections

## 8. Tools and frameworks

**ODM (Object Document Mapping) framework:** to map document objects into a NoSQL database like MongoDB. Eg: **Mongoose** (Node.js and MongoDB).

- MongoDB Atlas
- MongoDB Compass
- Mongo shell, CLI tools
- **Editions** *(correction: the notes said '3 versions')*: Atlas (cloud based, has a free tier), Community (free, self-hosted), Enterprise (paid, self-hosted)

**Connection string**

1. Local: `mongodb://username:<password>@localhost:27017/database_name`
2. Remote: `mongodb+srv://username:<password>@cluster0.mongodb.net/mydatabase?retryWrites=true&w=majority`

*(Never commit a real password in a connection string. Keep it in an environment variable.)*
